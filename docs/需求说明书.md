## 1. 项目概述

**跬步（Onestep）** 是一款面向 Android 与 Windows 双平台的**闪记卡（间隔重复）学习应用**。它借鉴 Anki / AnkiDroid 被千万用户验证过的数据模型与学习交互，但以**更简洁干净的界面、更简单的交互**重新打造，主打"打开就能背、上手零门槛"。

- 中文名：跬步（取"不积跬步，无以至千里"之意）
- 英文名：Onestep
- 平台：Android（手机/平板）、Windows（桌面）
- 形态：**本地优先（Offline-first）** + **多设备同步**（v1 内置），无网络也能完整学习，联网时可跨设备同步

### 1.1 设计目标（三条主线）
1. **简洁**：界面信息密度低、留白充足、单一主色调，不堆砌按钮。
2. **简单**：核心学习动作收敛为"看 → 翻 → 打分"三步，新手无需教学。
3. **可靠**：学习进度和数据绝不丢失，支持撤销、备份、导入导出、跨设备同步。

### 1.2 合规声明（重要）
- Anki（AGPL-3.0）与 AnkiDroid（GPL-3.0）的**源代码不可直接复制**到本项目，否则将传染本项目的开源义务。
- 本项目策略：**借鉴其数据模型、调度思想与交互范式，全部干净重新实现**。数据结构与算法思想不受版权保护。
- 调度算法采用 **FSRS**（开源、MIT 许可，参考 [open-spaced-repetition](https://github.com/open-spaced-repetition) 官方实现移植），可安全使用。
- APKG 导入为**只读解析**，不复用 Anki 源码，按公开格式规范重新实现。

## 3. 参考项目分析（我们取什么、舍什么）

### 3.1 从 Anki（桌面端）借鉴
- ✅ 成熟的**数据模型**：集合 → 牌组 → 笔记 → 卡片，笔记类型 + 模板 + 字段 + 标签。
- ✅ **笔记/卡片分离**：一条笔记可按模板生成多张卡片，字段复用。
- ✅ **完形填空（Cloze）** 类型。
- ✅ 卡片浏览器 + 搜索语法（Deck / Tag / State 过滤）。
- ✅ 统计图表（复习量、预测负载、保持率）。
- ❌ 舍弃：插件(add-on)生态、过于庞杂的选项面板、Qt 界面的陈旧观感。

### 3.2 从 AnkiDroid（安卓端）借鉴
- ✅ **离线优先**：无网络、无账号也能完整使用。
- ✅ **单手可完成的学习流**：底部大按钮打分，滑动/点按翻面。
- ✅ 桌面**小组件**（显示今日待复习数）、快速添加卡片入口。
- ✅ 夜间模式、字体大小适配。
- ❌ 舍弃：绑定 AnkiWeb 私有同步协议、较重的设置项、历史包袱 UI（我们用自研/开放的同步方案替代）。

## 4. 技术方案（已确认：Flutter）

### 4.1 选型
**Flutter**（Dart）：一套代码同时覆盖 Android + Windows，UI 精细可控，天然贴合"简洁干净"定位，开发效率最高。

### 4.2 技术栈
- **框架**：Flutter（Android + Windows）
- **状态管理**：Riverpod
- **本地存储**：SQLite（`drift`）——本地优先、支持事务与撤销
- **调度算法**：移植 FSRS（MIT），可配置"期望记忆保持率"
- **图表**：`fl_chart`（统计）
- **同步**：**自建轻量服务端**（Node/Go + 数据库），设备连它做差异合并同步，见第 6 节
- **导入导出**：CSV / TSV；**APKG 只读导入**（v1 内）

### 4.3 环境准备（开发前需要安装）
本机当前**只有 Node.js 与 Git**，缺少以下环境：
- Flutter SDK
- Android SDK（含 build-tools、platform）
- JDK（Android 构建需要）
- （Windows 打包）Visual Studio 桌面开发工作负载

> 开发正式开始前我会先安装并验证这套环境，再进入编码。

## 5. 功能需求（按模块）

优先级：P0 = v1 必须；P1 = v1 应有；P2 = 后续版本。
（注：本轮已将 **APKG 只读导入** 与 **多设备同步** 从"后续"提升进 v1）

### 5.1 数据模型（核心，P0）
- **集合 Collection**：应用的根数据容器。
- **牌组 Deck**：支持**嵌套子牌组**；每个牌组显示今日"新生/学习中/到期"数量。
- **笔记 Note**：一条知识事实 = 一组字段值 + 标签 + 所属笔记类型。
- **笔记类型 NoteType**：定义字段列表 + 卡片模板 + 样式；内置**普通（正面/背面）**与**完形填空（Cloze）** 两种。
- **卡片 Card**：由笔记经模板生成；携带调度状态。
- **调度状态**：状态机 `新卡 / 学习中 / 复习 / 重学`；字段含到期时间、稳定度(Stability)、难度(Difficulty)、复习次数、忘记次数、上次复习时间。
- **复习日志 ReviewLog**：每次作答记录，用于统计、撤销与同步。
- **媒体 Media**：图片、音频（P1 起支持）。
- **同步元数据**：每条记录携带 `修改时间戳` 与 `版本号`，用于冲突检测（见第 6 节）。

### 5.2 学习复习（核心闭环，P0）
- 牌组列表 → 点进牌组 → 复习流。
- 复习界面三步：**看问题 → 点按/空格翻面看答案 → 选评分**。
- 评分四档：**忘记 / 困难 / 良好 / 简单**，每档显示预计下次复习间隔。
- **撤销**上一次作答。
- 每日限制：新卡上限、复习上限（可配）。
- 完成本次的完成页（复习数、用时）。
- Windows：**键盘快捷键**（空格翻面，1–4 打分，Ctrl+Z 撤销）。
- Android：**手势/大按钮**单手操作。

### 5.3 卡片与笔记管理（P0）
- 新建/编辑笔记：选择笔记类型、填字段、加标签、选牌组。
- 完形填空（Cloze）语法 `{{c1::答案}}`，实时预览生成的卡片。
- 卡片预览。

### 5.4 多设备同步（v1 内，P0 —— 载体：自建服务端）
- 在多台已登录/已配对的设备间同步牌组、笔记、卡片与复习进度。
- 载体：**自建轻量服务端**（Node/Go + 数据库），设备连它同步，详见第 6 节。
- 冲突处理：基于时间戳/版本号的自动合并 + 冲突副本保留，绝不静默丢数据。
- 离线可学，联网自动/手动同步。

### 5.5 卡片浏览器 + 搜索（P1）
- 列表浏览全部卡片/笔记。
- 搜索与过滤：按牌组、标签、状态（新/学习/复习/已暂停）、字段内容。
- 批量操作：挂起/取消挂起、删除、移动牌组、改标签。

### 5.6 统计（P1）
- 每日复习量柱状图、未来负载预测、卡片状态分布、记忆保持率、连续打卡天数。

### 5.7 导入 / 导出（P0）
- 导入：CSV / TSV / TXT（映射字段）。
- **APKG 只读导入**（v1 内）：从 Anki 导出的 .apkg 文件导入牌组，供从 Anki 迁移。
- 导出：CSV / TSV（备份与迁移）。
- 手动/自动**备份**：启动时自动备份数据库，支持导出完整备份文件。

### 5.8 设置（P1）
- 新卡上限 / 每日复习上限 / 期望记忆保持率 / 学习步骤。
- 账号与同步设置（登录、配对设备、同步频率、冲突查看）。
- 主题：浅色 / 深色 / 跟随系统。
- 语言：默认中文，可切英文（i18n）。
- 字体大小 / 表现形式。

### 5.9 平台特性
- **Android（P1）**：桌面小组件（今日待复习数）、从其他应用"分享到"快速建卡。
- **Windows（P1）**：托盘/快捷启动、键盘快捷键、窗口记忆尺寸。

## 6. 多设备同步方案（已确认：A 自建服务端）

你要求 v1 内置同步，载体三选一后已确定为 **A 自建服务端**。

| 方案 | 说明 | 优点 | 缺点 | 工期影响 |
|---|---|---|---|---|
| **A. 自建同步服务端（✅ 已选）** | 我们提供一个轻量后端（如 Go/Node + Postgres/SQLite），设备连它同步 | 体验最好、可控、真·多设备 | 需要部署/运维服务端，用户要有服务地址 | 大（+后端开发与部署） |
| B. WebDAV 同步 | 复用现有 WebDAV 存储（如坚果云、Nextcloud）做中转 | 无需自建服务端，用户用现成网盘 | 并发冲突处理更复杂，依赖第三方可用性 | 中 |
| C. 端到端文件中转 | 通过一个共享文件夹/云盘里的加密包同步 | 最简单、隐私好（端到端加密） | 非实时、冲突需用户介入，体验一般 | 小 |

**落地要点（方案 A）**：
- 后端技术栈随主端一致，采用 **Node（或 Go）+ SQLite/Postgres**，提供账号/设备配对 + 差异同步 API。
- 客户端本地 **SQLite 照旧**，同步层在其上做**差异合并**（基于每条记录的修改时间戳 + 版本号）。
- 冲突策略：自动合并字段级/记录级冲突，无法自动合并的**保留双方副本**，绝不静默丢数据。
- 用户需配置一个服务地址（自托管部署）；离线时学习不受影响，联网后自动/手动同步。

> **离线学习能力不受影响**，同步只是在联网时叠加的一层。

## 8. UI/UX 设计原则

1. **一个主屏**：打开 App 首屏就是牌组/今日概览，学习入口一步直达。
2. **一屏一焦点**：复习时全屏只呈现当前卡片，底部仅评分按钮。
3. **少即是多**：高级选项折叠进"高级"，默认只暴露必要设置。
4. **柔和配色**：单一强调色 + 中性背景，浅色/深色双主题。
5. **可预期反馈**：每个动作都有即时视觉/触觉反馈，支持撤销。

**主要界面清单**：牌组列表 / 复习界面 / 完成页 / 新建·编辑笔记 / 卡片浏览器 / 统计 / 设置 / 同步与账号。

## 11. 验收标准（v1）

1. Android 与 Windows 双端均可安装运行同一套核心功能。
2. 能创建牌组与笔记（普通 + 完形填空），生成卡片。
3. 能完成"看 → 翻 → 打分"学习闭环，FSRS 正确计算下次间隔，支持撤销。
4. 每日新卡/复习上限、期望保持率生效。
5. 卡片可浏览、搜索、挂起、删除。
6. **可从 Anki 的 APKG 文件只读导入牌组**。
7. **两台设备登录/配对后可互相同步，冲突自动合并且不丢数据**。
8. CSV 可导入导出；启动自动备份，数据不丢。
9. 统计能反映复习量与卡片状态。
10. 浅色/深色主题，中文界面，界面简洁统一。
