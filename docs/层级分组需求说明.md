## 1. 术语与规则定义

- **层级深度**：根分组 = 第 1 层，其子 = 第 2 层……**最多 5 层**（即最深节点的第 5 层）。
- **完整路径**：`大模型::深度学习::卷积神经网络`（分隔符见 D1）。
- **子树**：某分组自身 + 其全部后代分组。
- **聚合口径**：父分组的"待学/已学/总数"= 自身卡片 + 所有后代卡片，**每张卡只计一次**。
- **同父唯一**：同一父分组下名字唯一；不同父下允许同名（`A::算法` 与 `B::算法` 是两个组）。

## 2. 功能清单（P0 = 本次必须；P1 = 应有；P2 = 后续）

### 2.1 数据层（P0）

- **P0-1 树构建**：`deckTree()` 返回按 (父, 名称) 稳定排序的森林；`pathOf(deckId)` 返回根到自身的路径；`descendantsOf(deckId)` 返回后代 id 集合；`depthOf(deckId)` 返回层数。
- **P0-2 深度校验**：`createDeck` 与 `moveDeck` 在超过 5 层时抛 `DeckDepthException`，消息里带上"当前 X 层，最多 5 层"。校验发生在写入前，不留半条数据。
- **P0-3 同父重名校验**：`createDeck` 在同一父下重名时按 D3 的策略处理（复用或报错）。
- **P0-4 环检测**：`moveDeck(id, newParentId)` 拒绝把分组移到自己的后代下（否则 `parentId` 成环，`descendantsOf` 会死循环）。
- **P0-5 删除级联**：`deleteDeck` 软删该分组**及其全部后代分组**与这些分组下的卡片；返回被删计数供 UI 如实提示。
- **P0-6 聚合计数**：`deckCounts(deckId)` 与 `dueCards(deckId)` 改为"子树聚合"口径（见 D2）。
- **P0-7 小组件口径修正**：`totalDue()` 改为**按卡片去重**统计，避免父卡重复计数导致桌面小组件数字虚高。

- **P0-14 XLSX 多层级解析**：`牌组` 单元格值按 D1 的分隔符切分成路径段；每段 trim；连续分隔符与空段丢弃（`A::::B` → `[A, B]`）；无分隔符时行为与现在完全一致（**向后兼容，旧文件照旧能导**）。

### 2.4 同步（P0/P1）

- **P0-23 补 parentId 回写**：`_applyRemote` 的 deck update 分支带上 `parentId`，否则跨设备改父会静默丢。

## 3. 数据模型

**不新增列、不做 schema 迁移。** 现有 `decks(id, name, parentId, deleted, version)` 足够。

```
decks
  id        TEXT PK
  name      TEXT        -- 仅本层名字，不含路径（"深度学习"，不是 "大模型::深度学习"）
  parentId  TEXT NULL   -- null = 顶层
  deleted   BOOL        -- 软删，级联时一并置 true
  version   INT         -- 毫秒时间戳，同步 LWW
```

**为什么不存物化路径（如 `path` 列）或 depth 列**：分组数量级很小（你当前 12 个组、上限 5 层），内存递归成本可忽略；加列要动 `schemaVersion` + 迁移 + 同步 payload，收益不划算。若将来分组上千再考虑。（见 D8）

**索引**：内存里建 `Map<(parentId, name), Deck>` 与 `Map<parentId, List<Deck>>` 两张表，一次构建 O(n)。

**软删与唯一性**：同父重名的判定只看 `deleted = false` 的行；已软删的同名组不阻塞新建（新建后是两条不同 id 的记录，靠 version 在同步侧 LWW）。

## 6. 需要你拍板的决策点（已按推荐默认值落地，结果见 6.1）

每条给出我的推荐默认值，你可以一句"都按你的建议"放行，也可以逐条改。

**D1 层级分隔符用什么？**
推荐 **`::`**。理由：Anki 与绝大多数闪记卡导出都用它，你以后从 Anki/闪记盒迁移不用改文件；`/` 在中文卡片正文里常见、易误切；多列模板要重做表头识别。
⚠️ 但这条依赖我验证不了的前提：**闪记盒导出的 xlsx 里层级到底怎么写**。样例文件已不在 Downloads。若它用的是缩进、多列或别的符号，导入就认不出来。**建议：你重新从闪记盒导出一次带子分组的文件给我，我实测它的列结构再定。** 拿不到就先按 `::` 实现，并保证"识别不出分隔符时行为与现在完全一致"（不破坏现有导入）。

**D2 父分组的"待学"数字和复习范围，聚合子树还是只看自己？**
推荐 **聚合子树**（Anki 语义）。价值：点父组一次把整棵子树背完，符合"打开就背"；只看自己会让父节点永远显示 0 待学，像个坏掉的入口。
代价：首页数字含义变了（原来"大模型 5 待学"只算直属卡，现在含子组）。若你更想要"父组只是目录、不参与学习"，选只看自己。

**D3 同一父下重名怎么办？**
推荐 **手动新建时报错提示"该分组下已存在同名分组"；导入时静默复用已有**。理由：手动场景你需要知道冲突，导入场景 320 行里弹 30 次错会毁掉体验。
（注意：这会改掉现有那条测试 `createDeck 支持同名分组共存` —— 它测的是"不同父/无父"，我会保留跨父同名允许，只收紧同父。）

**D4 导入遇到超过 5 层的路径怎么处理？**
推荐 **整批中止 + 列出全部超限路径**。理由：静默截断（`A::B::C::D::E::F` 变成都塞进 E）会让用户事后找不到卡片在哪，比导不进去更糟。
备选：截断合并（能导进来，但层级失真）/ 只跳过超限行（部分成功，报告里说明）。

**D5 删除父分组时，子分组怎么处理？**
推荐 **级联软删整棵子树**，确认框如实写影响面。理由：符合"卡片属于分组"的心智模型，且软删可恢复。
备选：子分组上提一层（保留数据但层级被打散）。

**D6 首页层级怎么呈现？**
推荐 **可折叠缩进树**（父行带箭头，默认展开到第 2 层）。理由：一屏看全貌，符合你"减少点击、状态常驻"的偏好。
备选：逐层下钻 + 面包屑（一屏更干净，但看全貌要点好几下）。

**D7 APKG 恢复层级（P1-21）本轮做不做？**
推荐 **本轮不做，放 M4**。理由：xlsx 是分组的唯一入口，先把主链路跑通；APKG 拍平是既有行为、没人报过问题，同时改两处会让导入回归面翻倍。

**D8 要不要加 `depth` 或物化路径列？**
推荐 **不加**。5 层 × 你当前 12 个组，内存递归完全够；加列要动 `schemaVersion`、迁移、同步 payload 三处，风险大于收益。

**D9 桌面小组件的待读数按什么口径？**
推荐 **按卡片去重后的全库待学数**（等价于所有顶层分组聚合值之和）。这条必须跟着 D2 一起改，否则父组聚合后小组件会**重复计数**、数字直接虚高一倍。

### 8.3 排序守卫的突变矩阵（2026-11-10 实测）

| 突变 | 期望变红 | 实测 |
|---|---|---|
| M1 退回只按 `queue`（原行为） | 「同一 queue 内按 due 升序」+「id 兜底」 | 2 红 ✓（id 那条报出 `Actual: ['card-z-3','card-m-2','card-a-1']` = 插入序） |

| M3 去掉 `id` 兜底 | 「id 兜底」 | 1 红 ✓（另两条仍绿，说明各键各归各的守卫） |

守卫故意**按 id 降序插入**卡片，好让"没排序"的结果（扫描序=插入序）与 id 升序不一致 ——
否则 SQLite 恰好会按插入序返回，测试就成了假绿。突变一律用 `grep -c REVERSE-CHECK` 确认
命中数=1 才算跑过；还原后与被测前基线 sha256 逐字节一致。
