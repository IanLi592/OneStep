# 跬步 / Onestep —— 本机构建说明（重要）

本项目在 DSH workspace-write 沙箱中开发。以下是经过验证的工具链使用方式。

## 工具链位置（都装在工作区内，无需管理员）
- Flutter SDK: `.tooling/flutter`（3.47.8 stable，Dart 3.13.7）
- JDK 17: `.tooling/jdk17/jdk-17.0.20.1+1`（Temurin）
- Android SDK: `.tooling/android-sdk`
  - `platform-tools/adb.exe`
  - `platforms/android-35`、`platforms/android-36`
  - `build-tools/35.0.0`、`build-tools/36.0.0`（含 aapt2）
  - `ndk/28.2.13676358`（`sqlite3_flutter_libs` 编译原生 SQLite 需要）
  - `cmdline-tools/latest`（注意：sdkmanager 自身联网失败，见下）
- Gradle 分发已预置到 `.tooling/gradle/wrapper/dists/gradle-9.3.1-all/<hash>/`
  （wrapper 的 JVM 下载器连不上 CDN，故用 Node 预下载放置）。
- `app/local.properties` 指向 `sdk.dir=D:\projects\Onestep\.tooling\android-sdk`
- 缓存重定向目录：`.tooling/cache`(AppData) `.tooling/pub-cache` `.tooling/gradle` `.tooling/tmp` `.tooling/home`
- 本地工具链不入库（见 .gitignore）。

## 网络（本机的坑，务必按此做）
1. **PowerShell/curl 的 SChannel TLS 栈损坏**（`SEC_E_NO_CREDENTIALS`）。
   一律**改用 Node.js（OpenSSL）下载**，见 `.diag/dl.js`：
   ```
   node .diag/dl.js <url> <dest> [sha256]
   ```
2. **sdkmanager 自身联网失败**（JVM 抓不到 repository manifest）。
   绕过办法：用 Node 直接下各 SDK 包 zip，解压并按 SDK 目录布局放置
   （脚本：`.diag/install-android.js` / `install-ndk.js` / `install-bt36.js`）。
3. **Gradle 首次下载分发失败** → 用 Node 预下载放进 wrapper 缓存
   （`.diag/install-gradle.js`，hash = base36(MD5(distributionUrl))）。
4. **Gradle 抓 storage.googleapis.com 偶发"无法知道是远程计算机"/卡死**（JVM 直连不稳）。
   已在 `.tooling/gradle/gradle.properties` 配置：强制 IPv4 + 走本地代理
   `127.0.0.1:12450` + 连接/读取超时（快速失败重试，避免无限挂起）。
   实测代理比直连快 ~5 倍且稳定。改此文件后需 `gradlew --stop` 重启守护进程。
   ⚠️ 该代理是本机环境（DSH）提供的；换机器时若无此代理，删掉
   gradle.properties 里的 `proxyHost/proxyPort` 行即可（直连也能通，只是慢）。
5. **APK 签名步骤写 `C:\Users\<user>\.android` 被沙箱拦**。
   解决：把 `ANDROID_USER_HOME` 也指向工作区
   （`.tooling/android-user-home`），debug keystore 就落在工作区内。

## Android APK 构建
```powershell
$tool='D:\projects\Onestep\.tooling'
$androidHome="$tool\android-user-home"; New-Item -ItemType Directory -Path $androidHome -Force | Out-Null
$env:ANDROID_USER_HOME="$androidHome"
$env:APPDATA="$tool\cache"; $env:LOCALAPPDATA="$tool\cache"; $env:PUB_CACHE="$tool\pub-cache"
$env:GRADLE_USER_HOME="$tool\gradle"; $env:JAVA_HOME="$tool\jdk17\jdk-17.0.20.1+1"
$env:ANDROID_HOME="$tool\android-sdk"; $env:ANDROID_SDK_ROOT="$tool\android-sdk"
$env:HOME="$tool\home"; $env:USERPROFILE="$tool\home"; $env:TMP="$tool\tmp"; $env:TEMP="$tool\tmp"
$env:GIT_CONFIG_GLOBAL="$tool\home\.gitconfig"
$env:PATH="$tool\flutter\bin;$env:JAVA_HOME\bin;$env:PATH"
Set-Location app
flutter build apk --debug    # ✅ 产物: build\app\outputs\flutter-apk\app-debug.apk (~152MB)
```
> 已验证：`flutter build apk --debug` 成功产出 app-debug.apk。
> debug 包较大（含各 ABI 原生库）；发布用下面「发版出包」的命令，不要直接手敲 `--release`。

## 发版出包（每次都必须先改版本号）
```powershell
# 1) 先 bump 版本号 —— 应用宝/Android 按 versionCode 判断"是不是更新包"，
#    不换号装上去可能还是旧包，白测一轮。versionName 含日期时间便于人眼分辨。
& 'D:\projects\Onestep\scripts\set-version.ps1'   # -> 0.1.0-<yyyyMMddHHmm>+<unix秒>

# 2) 再构建。--no-tree-shake-icons 不能省（见下方图标说明）。
cd 'D:\projects\Onestep\app'

flutter build windows --release --no-tree-shake-icons   # 产物: build\windows\x64\runner\Release\
```

>   'D:\projects\Onestep\app\build\app\outputs\flutter-apk\app-release.apk'
>
> # 版本号：核对 versionCode 是否真的变了（应用宝按它判断是不是更新包）

## PowerShell 脚本必须存 UTF-8 **带 BOM**
本机只有 Windows PowerShell 5.1（没有 pwsh）。它按 ANSI(CP936) 读**无 BOM** 的 .ps1，
中文字节会吃掉字符串终止符 —— 表现为 `UnexpectedToken` / `字符串缺少终止符`，脚本
根本没执行就报错。实测对照：

```powershell
# 语法检查（不执行脚本）
$t=$null;$e=$null
[void][System.Management.Automation.Language.Parser]::ParseFile(
  'D:\projects\Onestep\scripts\build-windows.ps1',[ref]$t,[ref]$e)
$e.Count   # 必须是 0
```
`scripts/build-windows.ps1` 曾经就是 2 个错（一直没被跑起来过，2026-11-10 补 BOM 修复），
`sync-server.ps1` 因带 BOM 一直正常。新增含中文的 .ps1 一律先补 BOM 再提交，
守卫见 `app/test/windows_artifact_path_test.dart`。

另一个坑：脚本里的 `flutter pub get` / `flutter build` 走的是 **PowerShell 自己的 PATH**。
从别的 shell 传进来的正斜杠形式（`D:/projects/...`）不生效，会报
`无法将flutter项识别为 cmdlet`。要么在 PowerShell 里按上面的写法设 `$env:PATH`（反斜杠），
要么用 `-Command` 一次性设好再 `& scripts\build-windows.ps1`。
2026-11-10 14:51 实测跑通：`√ Built build\windows\x64\runner\Release\onestep.exe`
（206,848 字节，增量 32.7s），脚本能正确列出产物目录。

## Flutter 命令（必须沙箱外 / danger-full-access）

需设置的环境变量（否则写到工作区外被拒）见上面"Android APK 构建"一节。

### 关键突破：符号链接补丁（免开发者模式）
Flutter 打 Windows 包要求能创建符号链接，而 Windows 默认需**开发者模式/管理员**才允许。
本机两者都没有（`New-Item SymbolicLink` 报"需要管理员"，HKLM 写入被拒）。

**解决**：给 Flutter SDK 打了一个本地补丁 —— 当符号链接因权限(错误码 1314)失败时，
回退用 `mklink /J` 创建**目录 junction**（junction 不需要任何特权，且对 CMake 的
`add_subdirectory` 与文件读取完全透明）。

- 补丁文件: `.tooling/flutter/packages/flutter_tools/lib/src/flutter_plugins.dart`
  （搜 `[ONESTEP PATCH]`），原文件备份为同名 `.bak`
- 改动点: `link.createSync(path)` 的 catch 分支 + 新增 `_createJunction()` 辅助函数
- 改完需**删快照强制重编译工具**:
  ```powershell
  Remove-Item .tooling\flutter\bin\cache\flutter_tools.snapshot -Force
  Remove-Item .tooling\flutter\bin\cache\flutter_tools.stamp -Force
  ```
  然后跑任意 flutter 命令（会自动重编译，约 1 分钟）
- ⚠️ Flutter SDK 升级/重装会覆盖此补丁，需重新打
