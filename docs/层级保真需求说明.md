## 5. 需要你拍板的决策点

每条给推荐默认值。**E1 和 E5 有真实的数据损坏风险，建议优先看这两条。**

**E0 要不要现在做？做哪一半？**
推荐 **先做 M1（CSV），M2（APKG）单独一轮**。理由：CSV 的备份丢层级是你**每天都在用**的路径，
而 APKG 是"从 Anki 迁一次"的一次性动作，且你自己手上没有待迁的 .apkg 就没法实测；
两件事一起改，导入回归面翻倍。你若同意，我就只做 M1。

**E1 `牌组` 列放最后一列，还是放第一列？**
推荐 **放最后**（`正面,背面,标签,牌组`）。理由很硬：现在的表头识别只看首列
（`csv_service.dart:54-58`），把牌组插到首列会让所有老文件的表头行**识别失败**，
于是 `正面,背面,标签` 这一行会被当成一张卡导进库里 —— 这是脏数据，不是不兼容。
代价：列序不符合"目录在前"的直觉，且 Excel 里往右滑才看得到。

**E2 `exportLibrary` 导出的 CSV，一次能导回多少？**
推荐 **一个文件全量导出 + 全量恢复**（按牌组列建组）。
备选：仍按组一个文件（打包成 zip）。全量单文件对"备份"更友好（一个文件一个日期），
缺点是这样导出的文件里同一张卡若属于多个组会重复出现 —— 我们的模型是一张卡一个 `deckId`，
所以实测不会重复，这条风险可以排除。

**E3 CSV 导入时看到 `牌组` 列，要不要自动按它建组？**
推荐 **默认不建，给一个显式复选框「按 CSV 的牌组列重建层级」**。
理由：现在导入是"选一个目标组，全塞进去"的心智；如果文件里恰好有一列我们就偷偷建组，
用户点的是"导入到《默认牌组》"，结果树里多出七个组 —— 这与"不要只报问题不给出口"同等的
底线是：**不要给意外的好处**。勾选后走 `ensureChain`，与 XLSX 同口径。

**E4 路径里的组名与已有组冲突怎么办？**
推荐 **按 (有效父, 名) 复用已有组**（与 XLSX 完全一致，`collection_repo.dart:150` 的
`_siblingNamed` 已经是这个口径），不报错、不建第二份。
导入场景弹 30 次冲突提示在 D3 已经被否过一次，这里沿用。

**E5 组名里含 `::` 的存量数据怎么处理？**
现状（读代码确认）：`createDeck` 不禁止 `::`，所以库里可能存在名叫 `A::B` 的组；
导出成 `牌组` 列后再导入，会被 `splitDeckPath` 切成两层 —— **备份-恢复不闭合**。
三个选项，推荐 **①**：

1. **禁止新数据**：`createDeck`/`renameDeck` 校验组名不得含 `::`，报可读错误；
   导出时遇到历史脏名字，把该组整条**跳过并在报告里列出**（不静默改造名字）。
2. 转义：导出时把组名里的 `::` 换成 `\:\:`，导入时反转义 —— 兼容性最好，
   但文件不再能被 Excel 直接读懂，且要新写一对转义/反转义函数与测试。
3. 不管：接受"含 `::` 的组名不能过 CSV 往返"。

价值对比：①用 20 行代码把口子封住，且失败是**响的**；②多养一套编码规则，
收益只是让极少数手工命名的库能过往返。所以我推 ①，②不值得。

**E6 APKG 恢复出来的层级，挂在哪儿？**
推荐 **给了 `targetDeckName` 就挂在它下面（作为一棵子树），没给就按 Anki 的顶层原样建**。
理由：现在"选一个组导入"的入口语义是"别污染我的树"，保持这个承诺；
而直接导入（不选组）时保真优先，别再多造一层假根。

**E7 Anki 的层级比 5 层深时？**
推荐 **沿用 D4：整批中止 + 用 `::` 列出所有超限路径**。
必须说清的代价：Anki 里 `X::Y::Z::W::V::U` 这种深度并不罕见，选"中止"意味着
**某些 .apkg 会一个字符都导不进来**。备选：① 把超出 5 层的后缀并进第 5 层的组名
（`E::F` → 名字 `E-F`），能导进来但层级失真、且名字被改；② 只跳过超限子树的卡
（部分成功）。如果你更希望"先能搬进来再说"，这条就该改成 ① 或 ②，你定。

**E8 重复导入同一个 .apkg 的幂等键是什么？**
推荐 **完整路径字符串**（`A::B::C`）作为复用键，落到同一个组。
不这么做的话，第二次导入会因为 `_ensureDeck` 的全局名查询而把卡塞进"别的地方的同名组"，
这是当前代码里已经存在的错，P0-2 就是为了堵它。

**E9 既然 CSV 根本没接到界面上，这轮做到哪一步？**
推荐 **做完 P0-0（设置页两个动作：导出全库 CSV、从 CSV 恢复）+ P0-3/4/5/6**。
理由：只加列不接入口，等于把一个"文档说支持、实际点不到"的问题改写成"代码里更完整、
实际还是点不到"，用户收益为零。
备选 A：先改 README 承认未接入，本轮只做 APKG（M2）——那 §8.2 第 8 条就该重写成
"CSV 通道未接入 UI"，而不是"导出无牌组列"。
备选 B：只做领域层 + 单测，UI 留下轮（我不推荐，理由同上）。
